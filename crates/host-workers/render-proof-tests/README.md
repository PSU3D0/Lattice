# host-workers/render-proof-tests

Render→run proofs (packets W2 + T3, ops/phase1-clone-engine-plan-2026-06-12.md):
the gate that says the wrangler.toml produced by `flows deploy render` is real.

- `src/lib.rs` — one worker, two proofs. `fetch` serves ONLY the `s1_echo`
  example flow through the existing host-workers entry machinery
  (`host_workers::handle_fetch` + `get_bundle()`, same shape as
  `../workerd-tests` and the s7 fixture); its runtime needs are exactly what
  the renderer emits for s1_echo: one `FLOW_DO` Durable Object. `scheduled`
  serves the cron proof flow through `host_workers::handle_scheduled`
  (byte-equal cron routing, `FLOW_DO` + `FLOW_KV`).
- `src/index.test.ts` — parses the RENDERED wrangler.toml with wrangler's own
  config parser and derives the entire miniflare setup from it (entry script,
  compatibility date, DO bindings + sqlite migrations, kv/r2/vars), then
  invokes `POST /echo` and asserts the flow executed.
- `src/cron.test.ts` — same derivation from `cron/wrangler.toml` (rendered
  from a requirements manifest the `emit-cron-requirements` bin DERIVES from
  the flow), then dispatches miniflare scheduled events with the cron strings
  read from the rendered file. Asserts: the flow ran (KV record keyed on the
  scheduled time), scoped capabilities (CAP110) held during the fire (an
  undeclared KV access fails the run), and an unroutable cron errors loudly.

`wrangler.toml` and `cron/` here are generated by `npm run render` /
`npm run render-cron` and gitignored — never hand-written; that is the point.
(`cron-bindings.lock.json` is a committed fixture supplying the KV namespace
id so the rendered cron config is placeholder-free.)

## Run

```bash
npm install   # once
npm test      # = flows deploy render + ensure-worker-build guard + vitest
```

`worker-build >= 0.7` must be on PATH (one-time `cargo install
worker-build@^0.7`, or set `LATTICE_AUTO_INSTALL_WORKER_BUILD=1` — see
`scripts/ensure-worker-build.sh`).
